# channel: Cisco ACI (APIC-controlled fabric) is the primary target of this channel; the same controller-REST pattern generalizes to Cisco Catalyst SD-WAN Manager (vManage) as a sibling channel. Both are controller-based fabrics that are NOT assessable via device 'show' text (the engine's only ingestion mode today), so each needs a read-only REST collector. This spec centers on APIC; vManage is the parallel case (near-identical parser delta and firing-finding shape).

## channel
APIC northbound REST over HTTPS (the same API the GUI and moquery use). READ path: class queries GET https://<apic>/api/node/class/<mo>.json (cluster-wide MIT scope) and GET https://<apic>/api/class/<mo>.json; MO/DN queries GET https://<apic>/api/node/mo/<dn>.json. Verified query modifiers: query-target={self|children|subtree}, target-subtree-class=<class>, rsp-subtree-include=faults|health, query-target-filter (e.g. eq(faultInst.severity,"critical")), order-by, and pagination page / page-size. JSON is requested via the .json suffix (XML via .xml). moquery is only a CLI wrapper over this same class-query verb, so the collector calls REST directly over HTTPS/443 (no SSH, no device login). SIBLING channel - Catalyst SD-WAN Manager (vManage): GET https://<mgr>:8443/dataservice/... (/dataservice/device, /dataservice/device/control/connections, bulk /dataservice/data/device/state/ControlConnection, /dataservice/device/action/status, /dataservice/device/monitor). This is purely ADDITIVE to the engine's existing SSH show-text channel (IOS/IOS-XE/NX-OS/IOS-XR keep SSH; controller fabrics gain REST).

## auth
APIC: token (cookie) model, GET-only for a collector. POST https://<apic>/api/aaaLogin.json with body {"aaaUser":{"attributes":{"name":"<user>","pwd":"<pass>"}}}; the response carries the session token at imdata[0].aaaLogin.attributes.token, also returned as the Set-Cookie value APIC-cookie. Every subsequent GET resends it (header 'Cookie: APIC-cookie=<token>'). The session has a server-set timeout (aaaLogin attribute refreshTimeoutSeconds, e.g. 600s); keep it alive with GET /api/aaaRefresh.json before expiry (the token ROTATES on each refresh). aaaListDomains is callable pre-login. A read-only collector MUST use a dedicated AAA account bound to a read-only RBAC role (custom role with read privilege on the fabric/admin/ops security domains, no write) - APIC RBAC is the hard control since the SAME token can POST. Prefer a client cert / TLS-pinned CA over plaintext creds; never store the password in the snapshot. vManage parallel: POST /j_security_check (form-encoded j_username/j_password) -> JSESSIONID cookie, then GET /dataservice/client/token for the X-XSRF-TOKEN header required on later calls; also a read-only user.

## key_objects

- fabricNode  (GET /api/node/class/fabricNode.json) - fabric inventory: id, name, role(leaf|spine|controller|unsupported), model, serial, version, fabricSt(active|inactive|disabled|decommissioned), adSt - L1/asset truth + decommissioned-but-present detection
- topSystem  (GET /api/node/class/topSystem.json) - per-node system facts: oobMgmtAddr, podId, state(in-service), currentTime, serial, role, fabricDomain, tepPool - reconciles APIC count vs in-service count
- faultInst  (GET /api/node/class/faultInst.json?query-target-filter=eq(faultInst.severity,"critical")) - active faults: code(F-codes), severity(warning|minor|major|critical), lc(lifecycle: soaking|raised|raised-clearing|retaining), ack, domain, cause, rule, dn, descr - the PRIMARY broken-state source (filter lc=raised AND ack=no to drop acknowledged/clearing noise)
- fabricHealthTotal  (GET /api/node/class/fabricHealthTotal.json) - fabric-wide overall health score: cur(0-100), maxSev - single rollup gauge
- healthInst (rsp-subtree-include=health on fabricNode/topSystem) - per-node health score (cur) to flag degraded nodes
- lldpAdjEp  (GET /api/node/class/lldpAdjEp.json) plus fabricLink / fabricNodeIdentP - L1/L2 fabric topology (leaf<->spine adjacencies) for SPOF / underlay reconstruction
- ethpmPhysIf + l1PhysIf  (GET /api/node/class/ethpmPhysIf.json) - physical interface operSt(up|down)/operSpeed/operDuplex - access/underlay L1 health
- fvCEp + fvIp  (GET /api/node/class/fvCEp.json) - learned endpoints (MAC) and their IPs/EPG - the endpoint census equivalent of show mac-address-table / ARP
- fvTenant / fvBD / fvAEPg / l3extOut  (GET /api/node/class/fvBD.json etc.) - L2/L3 logical service inventory (bridge domains, EPGs, L3Outs) for service-health and migration move-group scoping
- infraWiNode / vmmDomP - APIC cluster-member fitness and VMM (vCenter) domain integration state
- vManage: /dataservice/device (system-ip, reachability=reachable|unreachable, device-model, version), /dataservice/device/control/connections (state=up|down, local-color, peer-type=vbond|vsmart|vmanage|vedge, expected vs actual), /dataservice/data/device/state/ControlConnection (bulk), /dataservice/device/action/status + template attach (config out-of-sync)

## parser_strategy
ARCHITECTURAL DELTA: today the pipeline is cmd_to_file{show-string -> file path} -> cmdio._load_cmd_output() reads TEXT -> parse.py regex parsers -> build_*/compute_* -> a flat snap_dict[<axis>] assembled in COLLECT_PARSE_V3_23_0.py (~L2100-2170) -> _d_* detectors emit finding dicts {host,severity,kind,title,evidence} that fold into operational_drift / punchlist and reach every surface. The REST channel REUSES that entire downstream unchanged and only swaps the front door. Concretely: (1) NEW collector module (e.g. cisco_toolkit/rest_apic.py) mirrors collect(): instead of COMMANDS_NXOS (a flat list of show-strings) it iterates an MO-CLASS list [fabricNode, topSystem, faultInst, fabricHealthTotal, ethpmPhysIf, lldpAdjEp, fvCEp, ...], does aaaLogin once, GETs each class .json, and writes one raw JSON file per class into the collection dir (so --no-collect re-analysis works identically and the JSON stays auditable evidence). (2) NEW thin loader json_obj = _load_json_output(class_to_file, 'faultInst') beside _load_cmd_output - same skip-empty/skip-error contract, but json.load instead of f.read()+regex. (3) NEW build_apic_* normalizers fold imdata[].<class>.attributes into the SAME per-device dict shapes the engine already uses, keyed by node name/dn (so APIC nodes become 'hosts' like SSH devices and the device-identity axis stays unified). They populate NEW snap_dict keys: snap_dict['aci_inventory'], snap_dict['aci_faults'], snap_dict['aci_health'], snap_dict['aci_topology']. (4) NEW _d_aci_* detectors read those keys and emit the standard finding dict, folding into the existing operational_drift/punchlist arrays exactly like _d_vpc_health / _d_nve_peer_health do today. NET: parse.py gains JSON normalizers (no regex), analyze.py gains _d_aci_* detectors, COLLECT_PARSE gains ~4 snap_dict assignments plus a collector branch keyed off a device 'kind':'apic' in devices.json. Build/analyze/detector/deliverable/explorer layers are untouched in SHAPE because everything still flows snap_dict -> findings. The only genuinely new surface is HTTP/auth/pagination (http client + token refresh + page loop) and the MIM-attribute->engine-field mapping table; the harder part is SEMANTIC (mapping ACI's MIT/health/fault model onto an L1-L4 frame built for CLI state).

## firing_findings

- ACI-FAULT-CRIT: an UNACKNOWLEDGED raised faultInst at severity=critical (lc=raised AND ack=no) -> Critical finding citing code (e.g. F1394 port-down, F0321 cluster degraded), dn, descr. Broken-STATE: a fault object exists and is raised, not inferred from absence.
- ACI-FAULT-MAJOR: raised severity=major faultInst (lc=raised, ack=no) -> High finding, same evidence shape. Surfaces hardware/programming faults (e.g. F3544/F3545) before they escalate.
- ACI-NODE-DECOMMISSIONED-PRESENT: fabricNode with fabricSt=decommissioned (or inactive/disabled) still present in the MIT -> High finding (stale/ghost node = cutover blast-radius + license/asset drift). Reads an explicit state value, not 'missing'.
- ACI-NODE-INACTIVE: fabricNode adSt=on but fabricSt=inactive (admin intends up, fabric reports down) -> High finding citing node id/role/serial - the controller's own admin-vs-operational divergence.
- ACI-HEALTH-DEGRADED: fabricHealthTotal.cur below threshold (e.g. <90 High, <75 Critical) and/or a per-node healthInst.cur degraded -> severity-banded finding citing the score and maxSev. A measured low score, never silence.
- ACI-CLUSTER-DEGRADED: infraWiNode / fault F0321-F0325 indicating the APIC cluster diverged/degraded leadership -> Critical (control-plane SPOF for the whole fabric).
- ACI-IF-DOWN-INFRA: ethpmPhysIf operSt=down on a fabric (leaf<->spine) link, corroborated by an ethpm port-down faultInst -> High finding (underlay link loss = reduced fabric bandwidth/redundancy).
- SDWAN-CONTROL-CONN-DOWN (vManage): a control/connections entry with state=down, or actual-connections < expected-connections to a vsmart/vbond -> High/Critical (edge losing its control plane). Reads the 'down' state value.
- SDWAN-DEVICE-UNREACHABLE (vManage): /dataservice/device reachability=unreachable -> High finding citing system-ip/host-name (controller declares the edge unreachable).
- SDWAN-TEMPLATE-OUT-OF-SYNC (vManage): device template attach status reporting out-of-sync / config drift vs intended -> Medium/High (deployed state diverged from design-of-record). NOTE: every detector keys on a PRESENT broken-state attribute (raised fault, decommissioned/inactive/down/unreachable/out-of-sync); a missing object or an unreachable APIC yields a COLLECTION-GAP / not-collected marker (Info), never a silent 'healthy' - preserving the engine's coverage-honesty doctrine (no absence-as-finding; 'not observed' never becomes 'healthy').

## effort
Effort: MEDIUM, ~2-3 focused build slices (roughly 1.5-2.5 eng-weeks for a production-grade read-only collector + 4-5 detectors + tests + one deliverable surface). The downstream (snap_dict -> _d_* -> punchlist -> deliverables/explorer) is REUSED, which is most of the savings. New surface = an HTTP/TLS client with token login+refresh+pagination, a MIM-attribute->engine-field mapping table, JSON normalizers in parse.py, and the detectors. BIGGEST ARCHITECTURAL RISK: the engine is structurally SSH-show-text and offline - it assumes evidence is flat files captured once, parsed by regex, with a device == an SSH host. ACI inverts three of those: (a) evidence is a live token-authenticated REST session with pagination and session expiry (a stateful network dependency the offline engine has never had); (b) the unit of truth is the controller's MIT object graph, not per-device CLI - so 'host' identity, the L1-L4 framing, and the health model must be re-mapped onto an object model designed around policy intent, not interface state; (c) read-only is enforced only by APIC RBAC, since the SAME token that GETs can POST - so the safety guarantee moves from 'we only run show commands' to 'we hold a least-privilege credential', a weaker credential-dependent boundary the doctrine must explicitly own. Secondary risk: fault/health semantics drift across APIC releases (F-code meanings, health weighting) - the mapping table needs versioning. Mitigation: validate against the DevNet always-on ACI Simulator (sandboxapicdc.cisco.com) before any customer fabric.

## recommendation
BUILD NEXT, but as a tightly-scoped vertical slice - this is the single highest-value coverage gap: APIC/ACI fabrics are entirely INVISIBLE to the engine today (zero L1-L4 or health signal from a controller-based DC), and the customer-agnostic (Universal-ASNE) direction will hit ACI fabrics routinely. SMALLEST VIABLE FIRST SLICE: a read-only APIC collector that authenticates (aaaLogin -> APIC-cookie, with aaaRefresh) and pulls just THREE classes - fabricNode, faultInst (filtered severity in {major,critical}, lc=raised, ack=no), and fabricHealthTotal - writing one raw JSON file per class into the existing collection-dir layout. Wire a single normalizer plus exactly two detectors: ACI-FAULT-CRIT and ACI-NODE-DECOMMISSIONED-PRESENT, folding into operational_drift/punchlist so they appear in the workbook/runbook/explorer for free. Validate end-to-end against the DevNet always-on ACI Simulator (sandboxapicdc.cisco.com) so no customer credential is needed for slice 1. This proves the JSON-ingestion delta (loader + snap_dict + detector) with minimal new surface; faults are the highest-signal, lowest-mapping-risk objects. DEFER the deep logical-service inventory (tenant/BD/EPG/L3Out move-group modeling) and the vManage sibling channel to slice 2+ once the JSON pipeline and the read-only-credential safety story are proven and codified in doctrine.
