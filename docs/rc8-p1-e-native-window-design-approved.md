## 3. Pre-navigation admission: exact order, no default handlers

`AtlasWebView621Loader` first checks §5 and the maintenance/namespace fence **inside the authenticated GUI child, before imports/profile creation**. It loads NetFX and approved assemblies by admitted absolute paths, applies the version-bound overlay, and imports only the Edge backend. Alternative backends never execute setup.

`AtlasEdgeChrome.on_webview_ready` **replaces**, never calls, upstream initialization/navigation. On the GUI thread it performs this order while the HWND is hidden:

1. Check successful Core initialization, runtime/process/UDF identity and required API capabilities.
2. Install Atlas NavigationStarting, FrameCreated/frame-navigation, NewWindowRequested, WebResourceRequested, permission, certificate, download and process-failure handlers; register `AddWebResourceRequestedFilter('*', All, CoreWebView2WebResourceRequestSourceKinds.All)`. The three-argument source-kind overload must cover document/iframe/shared/service-worker sources; the legacy overload is not accepted.
3. Suppress upstream popup/open-browser, download, WebMessageReceived, bridge-injection and deletion paths. Set web messaging, devtools, context menus, password saving/autofill and extensions off; retain standard origin-bound HTML file-picker/dialog behaviour, but deny renderer permission grants. Never install a certificate-acceptance handler. Read back effective settings.
4. Only after every check succeeds send POLICY_ADMITTED and navigate once to the admitted Atlas origin. Inspect actual NavigationCompleted success/status; do not trust pywebview loaded. Show the window only after DOCUMENT_READY (§8). Missing capability or handler-install failure aborts native admission and follows §6 fallback.

**URI policy:** `O=(scheme, canonical numeric IP, effective port)` comes from the parent's actual bound socket. Only that exact HTTP(S) tuple is allowed; parse URI components, reject userinfo, controls, malformed/encoded authorities, zone IDs and DNS aliases. IPv6 is canonicalized as an address, not compared by bracket spelling. No prefix matching, synthetic Origin/Fetch-Metadata headers, token injection or TLS relaxation. Recheck every top/frame redirect and resource request; forbidden resources receive a local refusal before forwarding.

Only an initial inert `about:blank` is allowed before admission, with no messaging or data. Top/frame file/data/custom-scheme and blob navigation are denied. Current same-origin HTTP iframes remain; DOM frame-to-frame postMessage keeps its existing origin/source guard. Native web messaging is disabled and its upstream handler removed: all page/frame attempts to send native bridge messages are refused, not reclassified as trusted by origin. Blob downloads require an embedded origin equal to O and an admitted O document. Passive image data/blob resources are not navigable documents and remain subject to existing content/size owners and the restrictive policy below; no new claim of SDK interception of opaque resources is made. Download rules are in §7.

`NativeResponsePolicy`, a packaging-owned ASGI response wrapper configured before SERVER_READY, supplies a **second, additive CSP** to native-marked responses: `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; connect-src 'self'; img-src 'self' data: blob:; font-src 'self' data:; frame-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'`. Existing CSP/security headers are retained. The adapter tags admitted document/frame/resource requests with fixed, non-secret `X-Atlas-Native: 1`; this header only selects tighter response restrictions and is never authentication. No token, Origin or Fetch-Metadata header is injected. This covers remote connect/WebSocket/resource paths that SDK interception alone must not be assumed to cover. The unmarked default-browser path retains the existing policy. Native admission requires the wrapper's configured policy digest; document proof checks actual native CSP headers. The same-origin iframe/Scope and download tests must pass under it; CSP failure is not solved by weakening it. No new endpoint, second server or frontend fact computation is added.

All popups are handled by Atlas, never upstream: same-origin user navigation can reuse the one window; external HTTP(S) user gestures are cancelled and offer **Switch to Browser**, which opens only the canonical Atlas URL after safe presentation teardown. The user re-clicks the external link there. Redirects/non-user popups and non-HTTP(S) links never invoke an opener. The safe opener's DLL/PATH hygiene is not treated as URI validation.

The Python socket guard does not control native runtime background traffic. These page/request controls are not an OS firewall; no broader no-egress guarantee is claimed. Multiple CSP policies are conjunctive; the added policy is an extra restriction, not a replacement for base protections ([CSP specification](https://www.w3.org/TR/CSP3/)). A required request/source-kind protection that is unavailable causes native refusal, not a weaker native mode. [SDK filter/source-kind contract](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2.addwebresourcerequestedfilter?view=webview2-dotnet-1.0.4129.50).

## 4. One profile owner; no upstream recursive deletion

`NativeProfileOwner` in `portable/native_profile.py` is the **only deletion owner**. Use SDK InPrivate mode and a fresh session UDF; replace `clear_user_data` with controlled disposal/exit notification, and remove upstream recursive deletion regardless of private-mode flags. InPrivate is not an erasure guarantee.

Resolve FOLDERID_LocalAppData through the current-user Known Folder API, then create a fresh Atlas session directory with a current-logon-SID-only DACL and non-inherited handles. Do not trust LOCALAPPDATA/TEMP strings. Hold directory/file identities, reject UNC/device/reparse aliases at every component, and compare effective runtime UserDataFolder with the admitted physical directory. Keep the browser group exclusive to this UDF. Cookie/cache/storage/crash material is CLIENT data, outside bundle, helper, custody, backup and artifact trees; user-selected downloads are a different ownership set.

After controller disposal, require the actual Environment.BrowserProcessExited event **and signalled held process handles/empty GUI job**, not a three-second sleep. This increment automatically removes **only an empty, still-identity-bound current session directory**. Nonempty, changed, linked, locked, unknown or crash-leftover profiles are retained and disclosed; it never recursively sweeps browser-generated contents. Later launches inspect at most 32 owned records without traversing uncertain roots; no record alone authorizes deletion. Reclamation of nonempty/uncertain leftovers is administrator/user-owned, with the app showing its known-folder location and client-data warning. At eight retained sessions or 512 MiB of safely enumerated retained data—or if a bounded inventory cannot establish the quota—prefer browser fallback. This intentionally trades automatic cache reclamation for a small, safe first release.

Closing evidence includes replacement/reparse/lock/multi-session/crash cases: unknown bytes survive; no profile cleanup runs before real browser exit. Proof artifacts never include a profile, crash dump, credential or private destination path.

## 6. One presentation supervisor, authenticated IPC, unchanged server lifetime

`NativePresentationSupervisor` in `portable/native_window.py` owns only the GUI/WebView group and presentation state. Keep the existing `uvicorn.run`, signal handling, lifespan and Store ownership; no ServerController, parent-quit wrapper or additional Store close. A narrow presentation-ready notification after actual bind and successful app/lifespan/frontend startup supplies the immutable origin O and public instance marker. It cannot stop the server, change work admission or claim backend idleness. Headless and early maintenance/engine dispatch preserve their existing paths.

All destinations below are defined states. CLOSED means no Atlas GUI and a still-running server/console; BROWSER means an automatic browser launch was accepted, not proof that it rendered; MANUAL_REQUIRED keeps the URL available and authorizes no new automatic presenter; an earlier GUI may still have unconfirmed teardown. Only actual server exit ends the server lifetime.

| State | Event and next state |
|---|---|
| WAIT_SERVER | Actual readiness → SERVER_READY; actual server exit/failure → PRESENTATION_STOPPED. |
| SERVER_READY | Native eligible → GUI_STARTING; browser-only/ineligible → BROWSER if the safe opener accepts, otherwise MANUAL_REQUIRED. No suitable automatic opener → MANUAL_REQUIRED. |
| GUI_STARTING | Authenticated HELLO and installed policy → POLICY_ADMITTED; startup timeout/process/IPC failure → RETIRING(fallback). |
| POLICY_ADMITTED | Verified initial document evidence → NATIVE; navigation/admission/startup failure → RETIRING(fallback). |
| NATIVE | Close → RETIRING(close); browser request → RETIRING(browser); actual fault → RETIRING(fallback). With an active native download, an ordinary close/browser request instead enters WAIT_DOWNLOAD with that intent. |
| WAIT_DOWNLOAD | Download is settled and handles closed → RETIRING(saved intent). While active, remain WAIT_DOWNLOAD with the existing GUI; a fault → RETIRING(fallback), recording any unsettled download INCOMPLETE. No backend idle check. |
| RETIRING(intent) | Proved owned GUI/WebView exit: close → CLOSED; browser/fallback → one safe opener attempt → BROWSER or MANUAL_REQUIRED. Unproven GUI teardown → MANUAL_REQUIRED, with no second automatic presenter. |
| CLOSED | Explicit Open in Browser → BROWSER or MANUAL_REQUIRED; otherwise remain CLOSED. Server/console continue. |
| BROWSER | Remain BROWSER through backend busy periods and stale GUI close/fault signals. No transition to NATIVE. An explicit repeat opener request may report failure while retaining BROWSER and printing the URL. |
| MANUAL_REQUIRED | Remain MANUAL_REQUIRED through backend busy periods, failed retirement or failed opener attempts. An explicit safe opener request may enter BROWSER only after GUI retirement is proved; otherwise keep the manual URL. |
| PRESENTATION_STOPPED | Terminal after actual server exit; retire only any owned GUI group. No extra backend cleanup or automatic browser launch. |

From every live state, actual server exit enters PRESENTATION_STOPPED. Ctrl+C is handled by the **existing server** signal/lifespan behavior, never a presentation close check. Presentation close/fallback/browser switching neither signals the parent to quit nor waits for global backend idleness. There is no automatic native retry. A later close-window-quits-app feature is separate work.

Create the GUI process suspended, assign a held Windows Job Object with kill-on-close and no breakaway, then resume; containment failure selects browser/manual before UI. Only GUI/WebView descendants belong to this job, never server/engine/maintenance workers. Bind SDK-reported browser identities to held creation identities and job membership; require the exclusive UDF, not a shared browser group. Parent death closes the non-inherited job handle. Never terminate by image name or reused PID.

Use a local named pipe rejecting remote clients, with current-logon-SID DACL. Inherit only a bootstrap read handle and query/synchronize parent-process handle through an explicit STARTUPINFOEX list; no sockets, DB/worker/job handles or credentials. Both ends verify OS peer PID against held process handle, creation time, SID and integrity; parent also verifies GUI-job membership. Bootstrap carries a separate random 256-bit presentation capability, session ID and O, never the auth token or public instance nonce. Close unused ends and make the channel non-inheritable before browser creation.

Closed `atlas.presentation-ipc/1` frames have schema/session/monotonic-sequence/type/typed-payload/MAC, UTF-8, at most 4 KiB and ten frames/second. Types only: HELLO/HELLO_ACK, POLICY_ADMITTED, DOCUMENT_READY, SHOW, CLOSE_REQUEST, BROWSER_REQUEST, DOWNLOAD_STATE, RETIRE_GUI, FAULT and GUI_STOPPED. Child waits for authenticated HELLO_ACK before imports/profile creation. DOWNLOAD_STATE reports only the one presentation-owned download; it grants no backend work or file-operation authority. Reject unknown keys, wrong peer/MAC, replay, wrong-state/order and oversize frames; coalesce duplicate faults. No command/evaluation/general file-operation RPC. Public receipts contain controlled reasons and identity hashes, never capabilities, credentials or private paths.

Limits remain presentation-only: 2s IPC handshake, 20s total native startup not reset by partial progress, then 5s graceful GUI retirement plus 5s owned-job exit observation. Use actual ProcessFailed, BrowserProcessExited, child exit and IPC EOF signals. No mandatory continuous DOM/network heartbeat or custom six-second hang classification. The initial fixed probe remains required for native readiness (§8); the printed URL provides a manual browser escape even if an unclassified UI hang prevents its button working. Coalesce failure into at most one automatic fallback. Never transfer cookies/tokens or resubmit work; warn about sign-in and unsaved form loss. These limits never shorten backend timeouts or terminate backend work.

## 7. Presentation close and bounded native downloads

Close, fallback and browser switch retire **only** the owned GUI/WebView group. Do not add a request/worker lease catalogue, Store/engine instrumentation, global admission latch or backend drain guarantee. Upload/generation/export can remain active when the GUI retires; parent PID, serving socket and existing server/console lifetime continue. No presenter-initiated worker termination, mutation replay or extra Store close occurs. Ordinary connection loss uses existing backend cancellation, incomplete-result, committed-data and recovery contracts; GUI retirement does not claim those operations completed or safely drained.

`AtlasWinFormsCloseGate` defers an ordinary FormClosing/browser switch only while the one native download is active. `AtlasDownloadController` reports its own settled state: either final publication is verified, or transfer/publication is explicitly INCOMPLETE with SDK cancellation/termination and all download writer handles closed. SDK Completed alone is not settled. Only then retire the GUI for the saved close/browser intent. On actual renderer/IPC failure, request cancellation if possible, record an unconfirmed transfer as INCOMPLETE and retire only the GUI job. An unproved teardown permits only manual continuation. This is not backend work tracking.

**Download admission, before any download-specific file creation or write:** replace upstream DownloadStarting/SaveFileDialog behavior, hold the SDK deferral and suppress default download UI. Allow only an admitted O document and admitted same-origin HTTP(S)/blob source, one active download, and a known finite expected byte count no greater than 128 MiB. Unknown/unsupported length or inability to observe cancellation/handle closure selects browser/manual continuation. The download slot and retained staging inventory are independent of profile quotas.

Resolve the private Known-Folder staging parent and the user-selected **existing** final parent first, using held physical directory handles. Admit both planned staging and final paths against the actual installation, all profile and custody roots and the existing protected-namespace set: active application, previous/rollback (including Atlas.previous), incoming, recorded helper, transaction/journal and backup subtrees, plus every other protected subtree recognized by the maintenance/namespace owners. Neither a fresh filename nor a location outside the current profile is sufficient. Reject paths inside or aliasing any protected root, all reparse/uncertain components, unsupported UNC/device/ADS namespaces and ambiguous spellings. Apply existing namespace canonicalization to both requested spelling and resolved physical identity, including case/short-name/extended-path aliases. Unknown protected-root inventory refuses native saving. Never invent a weaker desktop-only path test.

Hold staging-parent and final-parent handles, directory/file IDs and volume identity through completion. **V1 permits only the same supported local volume** and handle-relative, atomic, no-replace rename publication; no cross-volume copy, copy-allowed move or final-parent creation. Compare actual volume identities, not drive letters. A C: staging parent and USB E: destination is refused before staging-directory/file creation, SDK download acceptance or any target write. Read-only/disconnected/unsupported filesystems, uncertain identity or an existing target (file or directory) also refuse. Offer the browser path without passing along the rejected destination or automatically replaying an export/job. The user explicitly chooses a safe output location outside Atlas, profiles and custody in the browser.

Only after both paths and the same-volume operation are admitted may the controller create its unique, SID-private, attempt-owned staging directory/file. Disable any competing SDK save path. Revalidate parent identities, containment/protected-root exclusions, volume and target absence before accepting SDK writes and again before publication. Keep staged bytes private; observed bytes beyond the admitted length trigger cancellation and INCOMPLETE. SDK Completed proves only the staging phase. Require closed SDK writers, an exclusive held file, matching expected byte count and any engine-declared digest, and successful file flush before the same-volume rename. Reopen/read back the final file identity, length and content digest against the staged file before reporting final completion. Race-resistant handle-relative no-replace publication is a capability gate; if unavailable, use browser rather than a path-based check-then-move.

A full/read-only/disconnected drive, changed parent, collision, interrupted or uncertain publication never becomes a completed download, overwrites anything or deletes the sole completed staging copy. On an uncertain rename, reconcile source/final identity before any retry; ambiguity stays INCOMPLETE and preserves data. No cross-volume copy/interruption recovery service is included. Any interrupted/partial transfer and its private outcome record remain CLIENT data, excluded from bundle, custody/public artifacts and profile cleanup. After successful verified publication, only the empty, still-identity-bound attempt directory may be removed; profile cleanup never owns download bytes.

**Bounded retention:** at most one active native download and one retained incomplete attempt, with the 128 MiB known-length admission above. Persist the incomplete latch across launches; retaining any incomplete/uncertain item, or failing to establish a bounded staging inventory, disables further native downloads and directs the user to browser/manual continuation. Do not accumulate retries or auto-resume. Nonempty/unknown staging is never swept or deleted to clear the latch; the operator must recover/remove their CLIENT data explicitly before readmission.
