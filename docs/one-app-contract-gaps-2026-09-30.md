# Atlas One v2 -- contract gaps (ui_projection/1)

Every place a screen of the v2 prototype needed a fact the engine's UI contract (`cisco_toolkit.ui_projection`, schema `ui_projection/1`) does not provide. The page draws each of them neutral -- never computed in the browser -- and names it once per screen (a strip at the foot of the screen, a slim placeholder where a primary visual would sit, or a caption); every id links back to its entry below. This file is generated by `build.py` from `gaps.py`, and the build fails if the page and this register disagree in either direction.

Built over the engine-built fictional sample `sample_fleet.snapshot.json` (3,072,771 bytes, sha256 `9580aa092d490a13ba420b2cc670ddee026f6dbf93ecc5aeac2fc94cd7f13089`) with `ui_projection` from the ui-projection-2 worktree (branch `feat/ui-projection-slice2`). Payload and all 26 device documents validated against `ui_projection_schema()` with jsonschema 4.26.0 (Draft 2020-12).

Priorities: **P1** a primary screen's verdict or colour is neutral, or can mislead, without it; **P2** a secondary section renders as 'awaiting the engine', or a screen words around a missing code; **P3** nice to have / engineering detail. **Rank** orders the whole register for the next engine slice (1 = first); within a priority, a gap that lets a screen show something misleading today ranks above one that only leaves a section neutral.

### P1

#### 1. G15 -- STP root per device, and root uniqueness

- **Screens:** Topology > L2 crown and node drawer; 2.5-D L2 plane; VLAN page > Layer 2; Inventory > VLANs (STP root); Task test > STP-root questions
- **Needed:** for each (device, VLAN): is_root, root address, root priority and 'root not parsed' where the parser defaulted; and a VLAN-level verdict when more than one selected stp_roots row claims is_root (the VLAN's stp_root should then be unverified or caveated, not published bare)
- **Engine owner that could supply it:** build.build_stp_roots (stp_roots) + analyze.compute_vlan_cutover_matrix (vlan_cutover[].stp_root, stp_root_default_election)
- **Suggested contract home:** `vlan rows: stp_root gains a caveat or goes unverified when roots disagree; selections.stp_roots -> FactList of {host, is_root: FlagFact, root_address, root_priority}`
- **What the page shows today:** In this sample VLAN 30 publishes stp_root = access1 with stp_root_default_election = Yes and no caveat, while 17 of the 18 STP rows the contract selects for it report is_root: true. The page qualifies the crown (R?, dotted halo, caption), tags the inventory cell 'default election', says 'per-device root state not in the contract' in the node drawer (never 'no'), and keys STP-root task-test questions only on rows publishing default election = No (only VLAN 10 qualifies, so the question type is left out, not padded).

#### 2. G49 -- Dossier exposure consistency (absence semantics)

- **Screens:** Device page > Risk dossier; Findings > Risk register (exposure glyphs)
- **Needed:** exposure states whose absence semantics agree across axes. access13's dossier says 'Config hygiene: no captured running-config' while 'Security posture: 6 CIS check(s) failing' (a security row exists) and 'Golden drift: matches the config baseline' (100% of a 2-directive majority baseline); config_hygiene carries a row only for core1, so absence from that sparse, findings-only dict is read as 'no running-config'

## Not gaps (decided in the page, stated here so they are not re-filed)

- **Map geometry** (lanes, tiers, node order, cable ends, port-channel member count) is read from `cable_map` rows directly -- D9: geometry in the browser. Every node/link colour, badge and verdict comes from a contract fact or is drawn neutral with a gap id. Hosts within a lane are ordered numerically (layout).
- **Joins by exact key** the contract already publishes (device documents by host, VLAN rows by `selections.vlan_row`, endpoints by index, cable facts by `/cable_map/cables/<i>`) are layout. Filters, sorts and 'showing k of n' over rows on screen are layout. Tab counts are the contract's own totals.
- **Role landing, presenter beats, task-test questions, keyboard map** are UI-owned; the task-test answer keys are contract facts chosen by exact value match. An STP-root key must publish `stp_root_default_election = No` (unique root); in this sample only VLAN 10 does, so that question type is left out rather than padded.
- **Withheld states in this sample:** the page embeds 7,438 published, 2,886 not_collected and 190 collected_but_empty envelopes (a build count over the fleet payload and the 26 device documents, shared engine block counted once). `analysis_unavailable`, `not_assessed` and `unverified` do not occur in it; the page renders all six (Trust > State grammar shows each).
- **Unresolvable subjects:** 2,081 fact subjects name an address absent from the snapshot (withheld facts such as a sparse interface field); every `refs` pointer resolves (checked by the build). The drawer says 'absent from the snapshot' for those subjects and defers to the contract's reason (see G40).
